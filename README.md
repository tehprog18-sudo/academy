# Академия Ума. Клуб первых открытий — демо

Приложение для записи родителей с малышами 1–2 лет на тематические занятия (версия B).

## Почему сайт не «сломается» на GitHub Pages

- **Весь ассет-массив (JS + CSS) встроен в один файл `index.html`** — плагин `vite-singlefile`. Отдельных файлов с 404 не существует.
- **`base: "/detskie-zanyatiya/"`** задан в `vite.config.ts` — имя должно совпадать с именем вашего репозитория.
- **Маршрутизация через `HashRouter`** (`/#/app/schedule`) — никаких серверных редиректов не нужно, обновление страницы не даёт 404.
- **`public/.nojekyll`** — автоматически копируется в `dist`, GitHub не обрабатывает файлы Jekyll'ом.
- **База данных — LocalStorage** браузера (клиентская): записи, профили детей и расписание сохраняются после перезагрузки. Сервер не требуется.

## Публикация на GitHub Pages — 2 способа

### Способ 1. Автоматический (рекомендуется, уже настроен)

В проект уже добавлен workflow `.github/workflows/deploy-pages.yml`.

1. Создайте на GitHub репозиторий с именем **`detskie-zanyatiya`**.
2. Залейте код:
   ```bash
   git init
   git add .
   git commit -m "Академия Ума: демо-версия"
   git branch -M main
   git remote add origin https://github.com/<ВАШ_ЛОГИН>/detskie-zanyatiya.git
   git push -u origin main
   ```
3. GitHub: **Settings → Pages → Source: "GitHub Actions"**.
4. Через 1–2 минуты сайт доступен по адресу:
   `https://<ВАШ_ЛОГИН>.github.io/detskie-zanyatiya/`
5. Каждый новый `git push` в `main` автоматически обновляет сайт.

> После каждого пуша проверяйте вкладку **Actions** — первый билд занимает ~2 минуты.

### Способ 2. Вручную (без Actions)

1. `npm install && npm run build` — в папке `dist/` появится готовый `index.html`.
2. В репозитории создайте ветку `gh-pages` и залейте туда **содержимое папки `dist`** (там всего один `index.html` + `.nojekyll`).
3. Settings → Pages → Source: **Deploy from a branch**, ветка `gh-pages`, папка `/` (root).

### Если репозиторий называется иначе

Измените одну строку в `vite.config.ts`:

```ts
base: "/ИМЯ_РЕПОЗИТОРИЯ/",
```

и соберите заново. (Технически single-file сборка откроется и без этого, но корректный `base` — обязательная страховка для внешних ассетов.)

## Сборка и запуск локально

```bash
npm install     # установка зависимостей
npm run dev     # режим разработки
npm run build   # продакшен-сборка в dist/
```

## Telegram-уведомления (опционально)

Заявки «Тест-драйв клуба» и новые брони могут приходить в Telegram:

1. **@BotFather** → `/newbot` → получите токен.
2. Напишите боту, затем узнайте Chat ID через **@userinfobot**.
3. В приложении: админ → **Настройки** → вставьте токен и Chat ID → «Отправить тест».

## Структура «базы данных» (LocalStorage)

Данные хранятся в браузере с префиксом ключа `malyshki_app_*`:
пользователи, дети, типы занятий (10 тематик), сессии расписания (±неделя),
брони, заявки на тест-драйв, настройки Telegram.

Сброс к демо-данным: кабинет администратора → Настройки → «Восстановить демо-данные».

## Состав демо

- 10 тематических занятий для 1–2 лет (2-часовые встречи с родителем)
- Расписание на 3 недели вперёд + история
- Личный кабинет родителя и панель администратора
- Запись с проверкой возраста, лист ожидания, отмена брони
- Полностью клиентская логика — работает без сервера
